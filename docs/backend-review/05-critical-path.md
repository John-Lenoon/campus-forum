### 本人互动列表与下架竞争

- `InteractionService.list` 原先先取得已发布 ID，再通过允许作者读取待审稿的普通详情接口逐项组装。测试拦截真实 ID 查询完成后，通过另一真实 HTTP 请求改稿，再释放列表请求。
- `interaction-race-red.log`：两项均断言失败；作者列表返回 PENDING 稿，其他用户的列表返回 404。
- 修复为在同一次详情行读取中要求 PUBLISHED，捕获并跳过并发下架／删除的 404；其他异常仍上抛。本人 liked／favorited 保持原查询方式。普通分页不新增跨请求快照承诺。
- `interaction-race-green.log`：两项确定性测试及原互动／评论回归共 15 项通过，失败／错误／跳过 0。

### 视频完成回执丢失与状态回退

- 原 `VideoService.process` 将完成数据库写入的异常与媒体处理失败同样处理；`failProcessing` 只按 claim 更新，可把已经 READY 且绑定的资源改为 FAILED。
- `video-commit-red.log`：真实视频经真实 MQ／openGauss 处理；完成写入及提交后暂停，通过独立 HTTP 确认 READY，绑定帖子并审核发布；随后注入提交回执丢失。最终资源变 FAILED，断言失败。
- 修复为只将播放文件生成异常标记为处理失败；完成数据库写入异常向消费框架传播，保留数据库任务及租约恢复路径。完成／失败的条件更新均要求状态仍为 PROCESSING 且 claim 一致，避免已完成状态回退。
- `video-commit-green.log`：真实已提交并绑定的资源继续为 READY，期限保持 null、公开播放入口可读；重复消息经真实消费者处理后状态不变。定向测试及媒体回归共 11 项通过，失败／错误／跳过 0。
- 独立复核指出自动重投可能抢先触发原重复消费信号。`video-duplicate-green.log` 补充确认：停止该测试独立消费者并自然处理完既有消息，确认专属队列为空；发送一条重复消息并确认入队后恢复消费者，等待新调用完成，资源仍为 READY。没有清空共享队列。
- 故障注入是在真实 Mapper 执行并提交后模拟回执丢失；不声称覆盖所有网络或存储故障。
