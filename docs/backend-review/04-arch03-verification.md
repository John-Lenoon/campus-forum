# ARCH-03：媒体进程中断验证

2026-11-11。使用独立数据库、存储目录及 RabbitMQ 队列，通过真实 HTTP 上传有效视频并由真实 MQ 消费器转码。测试仅使用测试环境切面捕获指定资源的消费者线程；没有替换 FFmpeg、Mapper 或服务结果。

原始实现的有效红测 `arch03-red-verified.log`：确认视频的真实 FFmpeg 子进程已经输出分段且工作线程处于 `MediaTools.hls`；中断该线程后，任务状态变为 FAILED，但 3 秒观察期后子进程仍存活。测试在 finally 仅终止经资源 UUID 和 JVM 父子关系验证的进程。先前进程识别失败的试验不计为红测。

Windows 上 Java 的 ProcessHandle 未提供命令行；测试使用 CIM 核对 FFmpeg 命令行中的随机资源 ID，并同时核对为本测试 JVM 的子进程。测试库、队列在上下文关闭后只删除本次随机创建的目标。

修复后，`MediaTools` 在 FFprobe／FFmpeg 等待中断或超时时终止进程并等待实际退出，保留线程中断语义。定向测试 `arch03-green.log` 验证进程退出、任务 FAILED、文件大小在观察期间不再变化、失败视频无法绑定帖子。`arch03-regression.log` 中该测试及常规媒体回归共 11 项通过，失败／错误／跳过均为 0；其后测试夹具仅补充了自身生成视频进程的异常清理，最终全量回归另行记录。

本记录不将这次模块回归等同于 DEC-049 整体验收。完整 full-media 和最终 JAR 重启验证应针对后续所有整改后的生产代码重新执行。
