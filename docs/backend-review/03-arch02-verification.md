# ARCH-02：图片上传一致性验证

日期：2026-11-10；基线 `6cd42654d47fdf9e8994c36665796cfc0e07912b`。本记录覆盖图片上传的一致性，其他审查项及最终整体验收另行跟踪。

## 实际红测

测试专用 MyBatis 拦截器在真实 INSERT 完成后，令随后 SELECT 抛出依赖异常；未替换 Mapper 返回值。通过真实 HTTP 观察失败，随后用独立数据库查询和实际文件检查确认：**HTTP 503；数据库记录 READY；原文件不存在**。结果为 1 项失败、0 错误、0 跳过；原始日志 `arch02-red-verified.log`。当前实现已删除上传后的冗余读取，故成功请求不会再触发该注入；后续独立 GET 查询异常另有测试。

首次尝试保守保留文件后，又用写入前故障得到第二个红测：数据库无资源行而文件存在，现有清理只扫描数据库行，因此不能自动清理。日志 `arch02-orphan-red.log`。修改后的非 READY 预留流程先写数据库，预留不确定时尚无文件；写入已知失败时也没有无记录文件。

只读复核发现非 READY 图片的 MIME 尚未确定；允许读取会返回不符合契约的 null。红测 `arch02-intermediate-red.log` 实际 200、预期 404；修复后内部图片预留不作为已完成资源对外读取。

## 修复机制

- 先创建具有 24 小时期限的 IMAGE／UPLOADING 预留记录；该内部记录对资源读取返回 404，不能关联投稿或头像。文件写入从数据库登记成功之后才开始。
- 在 Spring `TransactionTemplate` 内锁定预留行，写入并校验真实文件，检查期限后更新为 READY、实际 MIME 和自就绪起 24 小时的期限。成功响应由本次结果构造，不额外查询数据库。
- 文件写入或格式校验在 READY 更新前失败时，删除部分文件；预留记录仍受既有期限清理。数据库写入或提交一旦可能发生，异常不盲目删除文件：事务可能已提交 READY，也可能保留 UPLOADING，二者均有记录和回收依据。
- 清理使用相同资源行锁。受控测试先使 READY 更新未提交，再令真实 openGauss 清理查询等待该锁，提交后验证清理重新判断期限、保留已续期文件。
- 这是利用现有 Spring 事务与 MyBatis-Plus 的局部实现，无新依赖、数据库表或产品接口。已成功上传、绑定及正常删除的规则保持不变。
