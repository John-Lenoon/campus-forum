每次 Playwright 运行新建 openGauss 数据库、Redis 容器和 RabbitMQ 队列，使用随机本地端口、随机测试账号及独立存储目录。运行结束清理本次数据库、Redis 容器和队列；报告和失败轨迹保留在 `target/playwright-e2e/<运行编号>/`。

## 运行

前提：JDK 21、Maven、Node.js、pnpm、Docker；本项目 Compose 中 openGauss 和 RabbitMQ 正常运行。首次安装浏览器后执行：

```powershell
docker compose up -d --wait
cd frontend
pnpm install --frozen-lockfile
pnpm exec playwright install chromium --only-shell
pnpm test:e2e
```

脚本从当前后端源码在独立目录打包，不覆盖现有运行中的后端 JAR。测试失败时命令返回非零退出码；不标记预期失败。可通过 `pnpm test:e2e --grep 详情页刷新` 单独运行。每次测试报告位置由命令输出；HTML 报告在该运行目录的 `report/index.html`，JUnit 汇总在 `results.xml`，截图和轨迹在 `test-results/`。

## 缺陷复现与最小修复点

1. **详情刷新丢失**：打开公开作品，再刷新浏览器。实际回到列表。`App.tsx` 的 `detail` 和 `screen` 仅存 React 内存，打开作品只调用 `setDetail`。最小修复应让作品标识可从浏览器导航状态恢复，并在刷新后按标识读取详情。
2. **后退丢失页码与视口**：进入第 2 页，滚动到作品并打开，再按浏览器后退。实际没有恢复第 2 页。当前页码、详情和滚动位置未写入可恢复的历史状态。最小修复应在详情导航前保存列表页码和滚动位置，并在历史返回、列表数据渲染后恢复；第 2 页未恢复之前不能声称视口恢复已验证。
3. **刷新时原列表消失**：登录管理员，审核一篇待审作品；在列表刷新响应返回前进入“发现作品”。实际仅显示加载提示。`refreshFeed` 设置 `loading=true`，列表渲染又以 `loading` 替换已有作品。最小修复应区分首次加载与已有数据的后台刷新，等待时保留旧列表，并在成功后更新；同时维持对过期响应的防护。

本次只补测试和记录，未修改上述产品行为。
